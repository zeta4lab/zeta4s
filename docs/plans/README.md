# docs/plans

진행 중인 구현 계획을 둔다. 파일 목록은 두지 않는다.

계획은 `../usage/`, `../design/`, `../gate/` 의 어떤 요소를 추가하거나 삭제할지 정한다.
목표 자체와 완성 여부는 `../roadmap/` 이 관리한다. 착수하지 않은 backlog 는 여기 두지
않는다 — 구현 계획이 없는 계획이 된다.

- 최상위(`docs/plans/*.md`)에는 **진행 중인 계획만** 둔다. 진행 중인 구현이 없으면
  비어 있는 것이 맞다.
- 구현이 끝나면 `usage`, `design`, `gate` 를 현행화하고 `roadmap` 의 `상태:` 를 완료로
  바꾼 뒤, 계획 문서를 지운다. 끝난 계획은 보관하지 않는다 — 이력은 Git commit 과 PR 이
  정본이고, 남겨 둔 계획은 현재 기준과 갈라진 채 인용된다.
