# docs/roadmap

목표, 구현 기준, 완성 여부를 관리한다. 파일 목록은 두지 않는다.

- `00-step-graph-runtime-roadmap.md` — 마일스톤과 완성 여부
- `backlog/` — 착수하지 않은 목표. **항목마다 파일 하나**를 둔다. 목표는 있고 구현 계획은
  없는 상태다.

backlog 를 roadmap 본문에 두지 않는다. 항목이 늘수록 roadmap 이 비대해지고, 마일스톤과
착수 전 목표가 섞여 무엇이 끝났는지 보이지 않는다.

문서 흐름:

1. `backlog/` 에 목표를 등록한다. 구현 기준과 완료 기준을 함께 쓴다. 완료 기준은 기계로
   확인 가능하게 쓴다 — 나중에 gate 로 강제할 수 있다.
2. 착수하면 `../plans/` 에 구현 계획을 쓴다. 계획은 `usage`, `design`, `gate` 의 어떤
   요소를 추가하거나 삭제할지 정한다.
3. 구현이 끝나면 `../usage/`, `../design/`, `../gate/` 를 현행화하고, 마일스톤에 담고,
   `backlog/` 의 파일을 지운다. 계획 문서도 지운다 — 보관하지 않는다.

현행화는 version tag 를 붙이는 단계에서 완료한다. tag 가 없는 개발 내용은 진행 중일
뿐이다. tag 시점의 `usage`, `design`, `gate` 가 그 tag 의 현황이다.

Roadmap version tag는 구현 묶음을 표시하는 내부 체크포인트다. 사용자가 별도로 정식 공개
릴리즈를 지시하기 전에는 하위호환 보장을 뜻하지 않으며, 현재 목표 구조를 위한 삭제와
근본 수정이 tag 사이에서도 우선한다.
